# Nat Def — Strategic Threat & Posture briefing

A daily intelligence-analyst-style briefing operation tracking ten geopolitical threads —
Iran/Hormuz, Russia/Ukraine, China/Taiwan, North Korea, Homeland/Hemisphere, Terrorism,
Europe/NATO, Cyber/Tech, Energy/Markets and Alliance architecture — against the current U.S.
strategy and intelligence documents in [`sources/SOURCES.md`](sources/SOURCES.md), with every
claim run through a verification gate before it is written down.

Twelve briefs deep, 8–29 August 2026. The methodology is
[`BRIEFING-PROTOCOL.md`](BRIEFING-PROTOCOL.md); everything else in this repository either
follows from it or is generated by it.

## Quick start

```bash
python3 -m natdef status      # where things stand
python3 -m natdef render      # ledger -> the four pages
python3 -m natdef build-app   # ledger -> natdef-console.html (one offline file)
python3 -m natdef validate    # the Step 6 gate
python3 -m natdef check       # all three at once — run this before committing
python3 -m natdef serve       # serve the live ledger; never goes stale
```

No dependencies. Standard library only, Python 3.11+. Tests:

```bash
python3 -m unittest discover -s tests -t .
```

## The shape of it

`intel-ledger.json` is the single source of truth — threads, sources, timeline, horizon,
node graph, the full archive, and the verification log. **Every artifact here is generated
from it.** Editing a generated file by hand is a defect: the next render discards the edit
silently, which is the drift this design exists to prevent.

| Path | What it is |
|---|---|
| `BRIEFING-PROTOCOL.md` | The instruction set. Read this for the actual methodology. |
| `intel-ledger.json` | Single source of truth. |
| `briefs/` | Every delivered brief, `INDEX.md`, and one retracted brief (kept, never deleted). |
| `sources/SOURCES.md` | The founding government documents this tracks against. |
| `natdef/` | The toolchain. One module per job; see `natdef/__init__.py`. |
| `templates/` | The two page shells. Strict tokens only — no logic in templates. |
| `tests/` | 114 tests, stdlib `unittest`, no pytest. |
| `docs/` | How this repository came to exist, and what was decided along the way. |

Four pages are generated, plus the console:

- **`index.html`** — the front door. Today's bottom line, the ten-thread movement strip,
  and a way into everything else.
- **`strategic-threat-briefing.html`** — the standing picture: the map, the full
  chronology, thirteen actor and theatre briefings, changed judgments, horizon, sources.
- **`node-map.html`** — every actor as a force-directed graph, each with a deep dive whose
  history / recent / horizon timelines are *computed* from the ledger, never duplicated
  into it.
- **`brief-archive.html`** — every brief by date, plus a catch-up digest: pick a window and
  get the net thread movement across it and every item that caused it.
- **`natdef-console.html`** — all of the above in one self-contained file with the ledger
  baked in, for a machine with no network and no copy of this repository. It goes stale on
  every ledger write; rebuild it each brief, and never file it with the briefs.

## Producing a brief

Open this folder in Claude Code and ask for today's brief — it reads
[`CLAUDE.md`](CLAUDE.md) and `BRIEFING-PROTOCOL.md` and follows them. The short version:

1. Read the ledger; check `brief_number` and `last_cutoff` against `briefs/INDEX.md`.
2. Sweep the watchlist over the actual interval since the last cutoff, however long it is.
3. Run every candidate claim through the Step 3 verification gate.
4. Update the ledger — **all eight sub-steps of Step 4**, including both 4.2 (revise
   `threads[]`) and 4.8 (append the archive entry).
5. `python3 -m natdef brief` — the brief is generated from the archive entry, so its prose
   and the ledger cannot disagree.
6. `python3 -m natdef check`. Do not deliver or commit on a failure.
7. Prepend a line to `briefs/INDEX.md` and commit.

## What this rebuild changed

This is a from-scratch rebuild of the toolchain, on the same data. The operation's history,
its briefs, its protocol and its ledger content were carried over verbatim; every script
was rewritten. The four things worth knowing:

- **`render.py` exists.** It was specified in `BRIEFING-PROTOCOL.md` from the beginning and
  no copy of it ever survived into any session. The four validator checks that depended on
  its output had been standing down with an explicit `SKIPPED` since the migration; they
  are now real, and `validate.py` reports **0 failures and 0 skips**.
- **"Retired claims cannot reappear" is implemented**, against a new `retired_claims[]`
  registry seeded with the two claims this operation has actually retired.
- **Briefs are generated from their archive entry**, which makes the Brief 011 defect —
  where the brief's prose and the live ledger disagreed for four days — structurally
  impossible rather than merely detectable after the fact.
- **Every citation resolves.** The 23 inline free-text citations written from Brief 011
  onward had no recoverable URLs — not even, contrary to the migration notes, in the
  delivered briefs, whose Sources tables carry no links at all. They were recovered and
  backfilled into `sources[]`, so an unregistered citation is now a gate failure.

Full account, including which previously-open decisions were resolved and how, in
[`docs/REBUILD-NOTES.md`](docs/REBUILD-NOTES.md). The earlier migration out of the
claude.ai Project is recorded in [`docs/MIGRATION-NOTES.md`](docs/MIGRATION-NOTES.md), which
is history now but still holds one item needing a human:
the user's OneDrive working folder may hold state no session has ever reached.
